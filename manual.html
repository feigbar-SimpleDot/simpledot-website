Worker 配置 / Worker setup

如何快速为 worker 添加压缩模型

在宿主机依次执行以下四条命令（示例容器名 hermes_coder）：

docker exec hermes_coder  hermes config set auxiliary.compression.base_url 'http://127.0.0.1:1234/v1'
docker exec hermes_coder hermes config set auxiliary.compression.model '你的模型名' # 有空格时用引号括起来，
docker exec hermes_coder hermes config set auxiliary.compression.api_key 'sk-xxx'   # 或任意本地服务要求的 key，不需要时可以不加，点号 . 在 key 里要转义
docker exec hermes_coder hermes config set auxiliary.compression.reasoning_effort none # 压缩模型不需要太强的思考，none关闭或者low就行

如何快速为所有 worker 明确工作边界

在 main 中发送下面这条信息，即可驱动所有 worker 完成自我审查和优化：

我现在要求你根据当前worker的配置（简介，能力边界），清晰划分每个worker的任务边界和能力边界，然后通知各个worker严格检查自己的SOUL和skill是否满足，如果有越界的可能，必须立刻进行修正。（注意，边界仅在team work任务中生效）。
你可以通过api直接给worker发送明确的通知要求，并且，请串行分发，而不是并行。知道所有worker完成检查和修正。

角色 Effort 配置 / Role effort setup

如何为不同的角色选择 effort 等级

根据前面的 full-dev-lifecycle 流程和角色定义，模型 effort（推理强度/思考预算）建议按任务的决策权重、复杂度和风险分成三档：

档位含义
High需要深度推理、多约束权衡、决策影响大
Medium结构化执行 + 适度判断
Low规则/清单驱动，歧义低

各角色推荐 Effort

角色推荐 Effort理由
Product ManagerHigh需求梳理、范围与优先级直接决定后续所有步骤，决策成本最高
Interaction DesignerMedium–High需要同理心与创造性，但仍有较清晰的输入约束
System ArchitectHigh技术方案、模块边界、接口是系统级决策，错误代价极高
Development EngineerMedium–High编码本身是执行型，但复杂逻辑、边界与可维护性仍需较强推理
Test EngineerMedium测试设计有结构，重点在覆盖与验证，常规用中档即可
Code ReviewerHigh必须站在更高视角检查质量、安全与设计一致性，强制换人
Document AuditorLow–Medium主要是对照检查同步性，规则明确，低档足够

落地建议

  1. 默认配置（可直接写入 worker registry）：

    • High：Product Manager、System Architect、Code Reviewer
    • Medium–High：Interaction Designer、Development Engineer
    • Medium：Test Engineer
    • Low–Medium：Document Auditor

  2. 动态调整：

    • hotfix / typo / config_change → 整体下调一档
    • 出现 loops 回流（测试/审查失败）→ 相关角色临时升到 High
    • 核心业务或高安全模块 → Architect + Reviewer 强制 High

这样分配能让高决策密度的步骤获得足够推理深度，同时避免在低风险步骤上浪费算力。

Hermes Agent 官方提供了插件 hermes-adaptive-effort：安装并启用该插件，重启 Hermes，使用 /hae auto 开启。

开启后，插件会用独立的 scorer 自动评估当前任务需要多少 reasoning，再动态选择 effort。Desktop 安装源里也已经把这个插件加进了 catalog。

在 worker 对应的 docker 中运行以下命令即可一键安装并启用：

hermes plugins install 'atostivint/hermes-adaptive-effort' --enable

但使用前还需要配置一个决策模型，具体请查看： hermes-adaptive-effort ↗
